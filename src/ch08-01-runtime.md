# 程序是如何运行的

## 编译

磁盘放进管理器，或者磁盘内容、服务器配置发生变化时，管理器会**重新编译**程序（`ManagerBlockEntity.rebuildProgramAndUpdateDisk()`）。编译分几个阶段（`ProgramBuilder.build()`）：

1. **词法与语法分析**：用 ANTLR 生成的 `SFMLLexer` / `SFMLParser` 解析源码。出现任何语法错误，编译都会立即终止；
2. **构建 AST**：`ASTBuilder` 把语法树转换成可执行的对象。这一步还会检查：
   - 定时触发器的最小间隔；
   - 标签长度（不超过 256 个字符）；
   - 正则表达式是否合法；
   - 服务器是否禁用了程序执行（`disableProgramExecution`）；
3. **检查资源类型**：确认程序引用的每种资源类型都存在、格式正确，并且没有被服务器禁用；
4. **静态检查（lint）**：生成警告，写到磁盘上（见[编译检查与警告](ch08-03-warnings.md)）。

只要有错误，管理器就不会运行程序，状态显示“**无效程序**”。

### 编译缓存

编译结果按**程序文本**缓存：两台管理器的程序一字不差时，第二台直接复用第一台的编译结果，即**同一个程序对象**。这对性能有好处，但也带来一个后果：保存在程序对象内部的状态，主要是 [`ROUND ROBIN`](ch04-08-round-robin.md) 的轮询位置，会在这些管理器之间**共享**。

服务器配置的版本号变化后，缓存会失效；编译出错的结果不会被缓存。

**源码依据**：`ProgramBuilder` 中的 `private static final WeakHashMap<String, CachedProgramBuildResult> cache`，以及 `if (useCache && errors.isEmpty()) cache.put(programString, ...)`。

## 每一刻发生了什么

管理器在**服务器每个游戏刻**执行一次 `serverTick`（前提是所在区块已加载）：

```text
manager.tick++                         -- 本地时钟加 1
if 需要重新编译: 重新编译
if 没有可运行的程序: 结束
program.tick(manager)
```

`Program.tick()` 的流程：

```text
for 每个触发器（按书写顺序）:
    if 不该在这一刻执行: continue
        -- 定时触发器：时钟 % 间隔 == 偏移量
        -- 红石脉冲触发器：有未处理的脉冲
    ctx = 新建一个独立的上下文（fork）
    trigger.tick(ctx)                  -- 执行语句块
    释放 ctx 中所有输入槽位
清空红石脉冲队列
```

**要点**：

- 同一刻里，多个触发器按**书写顺序**依次执行，前一个触发器搬完的结果，后一个能看到；
- 每个触发器的上下文是独立的，`INPUT` 不会跨触发器传递；
- 所有触发器执行完以后，红石脉冲计数才清零。所以同一刻里的多个红石脉冲触发器，看到的是同样的脉冲数。

## 语句块内的执行

语句块中的语句**从上到下**执行：

| 语句 | 执行时做什么 |
|---|---|
| `INPUT` | 把自己加入上下文的输入列表。**不访问任何方块** |
| `OUTPUT` | 收集所有输入的来源槽位、自己的目的地槽位，然后搬运（见[搬运算法](ch08-02-transfer.md)） |
| `IF` | 计算条件，执行对应的分支 |
| `FORGET` | 从输入列表中删除指定的标签 |

### 来源槽位只收集一次

一条 `INPUT` 语句的来源槽位（连同对应的数量和保留计数器），在它**第一次被某个 `OUTPUT` 使用时**收集，之后在同一次触发器执行中**缓存复用**。这就是“输入端限额在多个 `OUTPUT` 之间共享”的原因（见[工作模型](ch04-01-io-model.md)）。缓存会在 `FORGET` 删掉相关标签时，或者触发器执行结束时释放。

目的地槽位**每条 `OUTPUT` 每次执行都重新收集**，计数器也重新创建，所以输出端的限额是按每条语句、每次执行计算的。

## 标签和网络

程序要访问一个标签对应的方块，需要同时满足：

1. **磁盘的标签数据**里有这个标签和方块位置（用标签枪推送）；
2. 方块在管理器的**线缆网络**中（与线缆或管理器相邻）；
3. 方块在指定的方向上提供了对应资源类型的**能力（capability）**。

线缆网络和能力的查询结果都有缓存。偶尔缓存出错，会导致管理器“莫名其妙”停止工作。这时可以点击管理器界面的“重建线缆网络”，或者执行 `/sfm bust_cable_network_cache`。模组的“已知问题”示例也提到了这个现象。

## 区块加载

管理器只在所在区块**被加载**时运行。被访问的容器所在的区块也必须是加载的，否则线缆网络中的那部分无法访问。跨区块的大型网络，最好配合区块加载器使用。

<div class="note">

**提示**：管理器从存档加载时，本地时钟会被随机化。如果你的程序依赖精确的执行时刻，请使用 `GLOBAL` 时钟（见[定时触发器](ch03-01-timer.md#管理器时钟与全局时钟)）。

</div>
