# 搬运算法详解

本节详细描述 `OUTPUT` 语句执行时的完整过程。对应的源码是 `OutputStatement.tick()` 和 `OutputStatement.moveTo()`。

## 第 1 步：收集来源槽位

对上下文中的**每一条已登记的 `INPUT`**（按登记顺序），收集它的来源槽位：

```text
for 输入语句引用到的每种资源类型:
    for 标签访问解析出的每个 (标签, 方块):          -- 受 ROUND ROBIN 影响
        for 方向限定中的每个方向:
            能力 = 网络中该方块该方向上这种资源类型的能力
            if FROM EACH: 为这个能力新建一组计数器
            for 槽位编号 in 0 .. 能力的槽位数:
                if 不在 SLOTS 范围内 或 槽位为空: 跳过
                for 每个计数器（即每个资源限额）:
                    if 计数器匹配该槽位的资源（含 WITH、EXCEPT）:
                        生成一个“受限来源槽位”(槽位, 计数器)
```

不加 `FROM EACH` 时，同一条语句的所有能力共用一组计数器。

## 第 2 步：收集目的地槽位

对这条 `OUTPUT` 本身做类似的处理：

```text
for 输出语句引用到的每种资源类型:
    for 每个 (标签, 方块), 每个方向:
        if TO EACH: 为这个能力新建一组计数器
        for 每个槽位（在 SLOTS 范围内）:
            for 每个计数器:
                计数器.观察(槽位中已有的资源)           -- 用于 RETAIN，总是执行
                if 槽位可以作为候选:                   -- 见下文
                    生成一个“受限目的地槽位”(槽位, 计数器)
```

“槽位可以作为候选”的判断：

- 有 `EMPTY SLOTS IN`：槽位必须是空的；
- 否则：槽位容量上限大于 99 时，当前数量小于上限即可；不然，当前数量还要小于该物品的最大堆叠数。

## 第 3 步：两两搬运

```text
for 每个来源槽位:
    if 来源槽位已完成: continue
    for 每个目的地槽位:
        if 目的地槽位已完成: 移除并跳过
        moveTo(来源槽位, 目的地槽位)
        if 来源槽位已完成: break
    if 没有目的地槽位了: break
```

**来源在外层、目的地在内层**：每个来源槽位会依次尝试所有目的地，排在前面的目的地优先被填满。

## moveTo：一次搬运

`moveTo(来源, 目的地)` 会依次执行以下检查和计算：

1. 两者的资源类型不同 → 放弃；
2. 目的地的计数器不接受来源中的资源（资源 ID、`WITH`、`EXCEPT` 不匹配）→ 放弃；
3. **可搬量** = 来源槽位中的数量；
4. **处理输入端的 RETAIN**：
   - 减去之前已经在这个槽位“预留”的数量；
   - 如果计数器的保留义务还没满足，就从可搬量中再拿出一部分来满足它，并记在这个槽位上；
   - 可搬量 ≤ 0 → 标记来源已完成，返回；
5. **模拟插入**：看目的地实际能放进多少。放不进 → 返回；
6. 可搬量 = min(可搬量, 目的地能放进的量, 目的地计数器剩余额度, 来源计数器剩余额度, 单组最大堆叠数)；
7. **实际抽取**可搬量，**实际插入**目的地；
8. 两边的计数器都记下实际移动的数量；
9. 如果实际插入时有剩余（目的地在模拟时“说谎”，模拟时说能放进，实际却放不下），SFM 会在日志中记录 **“RESOURCE LOSS HAS OCCURRED”**（资源丢失）报告。这种情况属于其他模组的兼容性问题，可以关闭配置项 `logResourceLossToConsole` 来屏蔽这类日志。

### 输入端 RETAIN 的“先到先得”

从第 4 步可以看出，输入端的保留义务是**按访问顺序满足**的：先被访问的槽位先用来“充当保留”。

例如，`INPUT RETAIN 10 iron_ingot FROM a`，箱子 `a` 的 0 号槽位有 6 个铁锭，5 号槽位有 20 个：

- 访问 0 号槽位：6 个全部留作保留，还差 4 个；
- 访问 5 号槽位：再留 4 个，剩下 16 个可以搬走。

结果：一共搬走 16 个，`a` 中剩下 10 个。总数是对的，只是“留下的是哪些槽位”取决于访问顺序。

## 计数器的四种实现

根据数量和保留量是否带 `EACH`，每个资源限额会使用以下四种计数器之一（输入端和输出端各有一套）：

| 计数器 | 数量 | 保留量 |
|---|---|---|
| `SharedQuantitySharedRetention…` | 共享 | 共享 |
| `ExpandedQuantitySharedRetention…` | 按资源分别计算 | 共享 |
| `SharedQuantityExpandedRetention…` | 共享 | 按资源分别计算 |
| `ExpandedQuantityExpandedRetention…` | 按资源分别计算 | 按资源分别计算 |

输出端计数器的完成条件：已搬数量达到数量上限，**或者**“目的地已有 + 已搬”达到保留量。

## 一个完整的例子

```sfml
EVERY 20 TICKS DO
    INPUT 10 iron_ingot FROM a
    OUTPUT RETAIN 6 iron_ingot TO EACH b
END
```

假设：`a` 有 64 个铁锭；有两个 `b`，`b1` 已有 2 个铁锭，`b2` 是空的。

1. 收集来源：`a` 中所有铁锭槽位，共用一个“最多 10 个”的计数器；
2. 收集目的地：`TO EACH`，`b1` 和 `b2` 各有一个“补到 6 个”的计数器，观察结果为 `b1` 已有 2，`b2` 已有 0；
3. 搬运：
   - `a → b1`：min(64, 输入剩余 10, 输出剩余 6 − 2 = 4) = 4，`b1` 补到 6，输入计数器已用 4；
   - `a → b2`：min(60, 输入剩余 6, 输出剩余 6) = 6，`b2` 补到 6，输入计数器已用 10，完成。
4. 结果：`a` 剩 54 个，`b1`、`b2` 各 6 个。
