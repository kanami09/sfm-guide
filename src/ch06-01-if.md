# IF / ELSE IF / ELSE

## 基本形式

```sfml
EVERY 20 TICKS DO
    INPUT FROM source
    IF source HAS GT 10 iron_ingot THEN
        OUTPUT TO dest1
    END
END
```

`IF <条件> THEN <语句块> END`：条件为真时执行语句块，为假时跳过。

## ELSE 与 ELSE IF

```sfml
EVERY 20 TICKS DO
    IF a HAS GE 32 iron_ingot THEN
        INPUT 1 cobblestone FROM a
    ELSE IF a HAS GE 16 iron_ingot THEN
        INPUT 1 stone FROM a
    ELSE
        INPUT 1 red_sandstone FROM a
    END

    OUTPUT TO b
END
```

- `ELSE IF` 可以写任意多个，`ELSE` 最多一个，并且必须在最后；
- 从上到下依次判断，**只执行第一个为真的分支**；所有条件都为假时执行 `ELSE` 分支（如果有的话）；
- 整个结构只需要**一个** `END`。

<div class="note">

`ELSE IF` 在编译时会被转换成嵌套的 `IF`：`IF A THEN x ELSE IF B THEN y ELSE z END` 等价于 `IF A THEN x ELSE (IF B THEN y ELSE z END) END`。所以两者的行为没有任何区别。

</div>

## 嵌套

语句块中可以再写 `IF`：

```sfml
EVERY 20 TICKS DO
    INPUT FROM storage
    IF REDSTONE GE 1 THEN
        IF furnace HAS LT 8 coal THEN
            OUTPUT RETAIN 8 coal TO EACH furnace BOTTOM SIDE
        END
        OUTPUT RETAIN 16 iron_ore TO EACH furnace TOP SIDE
    END
END
```

## 条件在什么时候计算

条件在**执行到这条 `IF` 语句的那一刻**计算。前面的 `OUTPUT` 已经搬过的东西会反映在结果里：

```sfml
EVERY 20 TICKS DO
    INPUT FROM a
    OUTPUT 64 TO b

    IF a HAS EQ 0 THEN   -- 这里看到的是上面搬运完成之后 a 的状态
        INPUT FROM c
        OUTPUT TO b
    END
END
```

## INPUT 在 IF 之后依然有效

`IF` 分支里登记的 `INPUT`，在 `END` 之后**仍然有效**，直到被 `FORGET` 撤销或者触发器结束（见[工作模型](ch04-01-io-model.md#if-分支中的-input)）。反过来，`IF` 之前登记的 `INPUT`，在分支里也能用。

## 语法

```antlr
ifStatement : IF boolexpr THEN block (ELSE IF boolexpr THEN block)* (ELSE block)? END ;
```

<div class="note">

**关于编译期的模拟检查**：为了给出 “INPUT 没有被消费” 之类的警告，SFM 在编译时会把每个触发器内所有 `IF` 的真假组合**全部模拟一遍**（2ⁿ 种情况）。条件数超过服务器配置 `maxIfStatementsInTriggerBeforeSimulationIsntAllowed`（默认 10）时，就跳过这个触发器的模拟，部分警告可能因此漏报。这只影响警告，不影响程序运行。

</div>
